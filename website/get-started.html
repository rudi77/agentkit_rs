Get started

From zero to a running agent

agentkit installs as a single executable with no runtime dependencies. Without an API key it runs a built-in, network-free demo model, so you can verify the installation and try the pipeline behaviour before configuring anything.

1. Install

Windows: one command

No Rust, no clone, no admin rights. The setup script downloads the release binary, puts it into %LOCALAPPDATA%\Programs\agentkit\bin, adds that directory to the user PATH and creates a configuration template.

irm https://raw.githubusercontent.com/rudi77/agentkit_rs/main/scripts/agentkit_setup.ps1 | iex

Options go through a script block: -NoTui for the lean variant, -Version vX.Y.Z for a specific release, -WithExamples to unpack the examples, -Uninstall to remove it again.

Release binaries

Every v* tag publishes four binaries on the GitHub releases page: Windows and Linux, each in a full variant (with the terminal UI) and a CLI variant for scripts and CI. Both include PDF reading, context management, exact token counting, the knowledge graph, the work runtime and the trace viewer.

From source with cargo

# same feature set as the full release build
cargo install --path agentkit_app --bin agentkit --features "tui pdf ctxman tiktoken graph work viz"

# without the terminal UI
cargo install --path agentkit_app --bin agentkit --features "pdf ctxman tiktoken graph work viz"

The scripts/install.sh and scripts/install.ps1 scripts do the same and additionally set up shell completions. Later, agentkit --upgrade updates an installed binary in place.

2. Verify

agentkit --demo "What is 17 + 25?"
agentkit config show
agentkit --help

3. Configure a model

Credentials live in ~/.agentkit/config.json (Windows: %USERPROFILE%\.agentkit\config.json), created with agentkit config init. The file maps onto the same environment variables the rest of the code reads, and it is the lowest level of a three-level chain in which each higher level wins:

real environment variable  >  .env in the working directory  >  ~/.agentkit/config.json
ProviderVariables
Azure OpenAIAZURE_OPENAI_ENDPOINT, AZURE_OPENAI_API_KEY, AZURE_OPENAI_DEPLOYMENT
OpenAIOPENAI_API_KEY, optionally OPENAI_MODEL
Local or OpenAI-compatible (Ollama, LM Studio, vLLM, llama.cpp, LiteLLM)OPENAI_BASE_URL (e.g. http://localhost:11434/v1), OPENAI_MODEL; the key is optional
Offlinenothing, or AGENTKIT_PROVIDER=demo

Placeholders such as <your-key> count as unset, so a fresh template falls back to demo mode instead of failing against a bogus endpoint.

4. First steps

One-shot, REPL, TUI

agentkit "Explain what src/agent.rs does"       # one-shot in the current directory
agentkit --repl                                   # interactive session with memory
agentkit --tui -w . --skills ./skills             # terminal UI
agentkit --continue                               # pick up the most recent session

In a session, the agent asks for approval before every run_shell. Answer once, remember the program for the session, or make it permanent; /permissions shows the current rules. /undo reverts the last file change. /context shows what occupies the model's context.

As a Unix filter

# stdin is context, stdout is the clean result, the trace streams on stderr
cat data.json | agentkit --format json "Extract the total" | jq .total

agentkit -p "Summarise" < report.txt > summary.txt

# one profile per pipeline stage: prompt, strategy, tools, skills, MCP
cat src/lib.rs \
 | agentkit -p --profile agents/extractor.json "Extract all public functions" \
 | agentkit -p --profile agents/rater.json     "Rate each by complexity" \
 | agentkit -p --profile agents/writer.json    "Write a Markdown report"
Two things that surprise people. -p silences the whole tool trace, even with --steps; to keep stdout clean and see the trace, drop -p and use --format json --steps. And when stdin is not a terminal it is read to EOF, so a background invocation with an inherited, never-closed stdin will hang — always pipe something, even an empty string.

Safety switches

agentkit --dry-run "Rename every occurrence of foo to bar"   # destructive tools become no-ops
agentkit --verify "Fix the failing test"                      # nudge to run a check before finishing
agentkit --allow-read ~/reference "Compare with the spec"      # extra read-only sandbox roots

5. Go further

Context management for long runs

agentkit --ctx .agentkit/ctx --memory notes.jsonl "Review main..HEAD file by file."
agentkit --ctx .agentkit/ctx --ctx-policy policy.json --ctx-compaction-model gpt-5.4-nano --tui

A shared memory across sessions

agentkit --graph .agentkit/graph -w .            # read, remember, promote
agentkit --graph .agentkit/graph --graph-readonly

Work that outlives a run

agentkit work create --title "Graceful swarm shutdown" \
  --objective "Analyse the lifecycle, implement a controlled shutdown, add tests"
agentkit work run graceful-swarm-shutdown -y
agentkit work status graceful-swarm-shutdown
agentkit work watch graceful-swarm-shutdown      # live view in a second terminal
agentkit work resume graceful-swarm-shutdown     # after a crash or a pause

Watch a run in the browser

agentkit --trace .agentkit/trace "Analyse this crate"
agentkit viz --open                              # in a second terminal, live or afterwards

MCP servers

// .mcp.json in the workspace, Claude Code format, discovered automatically
{
  "mcpServers": {
    "git": { "command": "uvx", "args": ["mcp-server-git", "--repo", "."] },
    "azure": { "command": "npx", "args": ["-y", "@azure/mcp"],
               "tools": ["group_list", "storage_blob_list"] }
  }
}
agentkit --mcp git "Summarise the last commits"   # allowlist one server
agentkit --no-mcp "…"                              # MCP off

6. Use it as a library

The core needs no network to be exercised. Twelve lines with the fake model:

use std::sync::Arc;
use agentkit::{Agent, ToolRegistry};
use agentkit::testing::FakeLlm;
use agentkit::llm::Chunk;
use serde_json::json;

let mut tools = ToolRegistry::new();
tools.add("add", "Adds two numbers.",
    json!({"type":"object","properties":{"a":{"type":"integer"},"b":{"type":"integer"}},"required":["a","b"]}),
    |args| Ok((args["a"].as_i64().unwrap() + args["b"].as_i64().unwrap()).to_string()));

let llm = Arc::new(FakeLlm::new(vec![
    vec![Chunk::tool(0, "c1", "add", "{\"a\":17,\"b\":25}")],
    vec![Chunk::text("The result is 42.")],
]));
let mut agent = Agent::new(llm, tools);
println!("{}", agent.run("What is 17 + 25?"));

With a real model, replace the fake with agentkit::azure_from_env() or openai_from_env(). The examples directory holds runnable, offline demonstrations of sub-agents, a coding team, a PR review setup, a long accounts-payable pipeline, and every swarm topology.

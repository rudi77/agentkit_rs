Installing skills and plugins: what they contain, when they load and what the installer refuses

Suppose you want to ask questions about a 100-page contract. A coding agent can read the file, but it has no procedure for long documents: how to split one, where to look first and how to cite a passage. Such a procedure is a few pages of text. agentkit 0.33 can install that text once and load it in later runs.

This article explains the two forms the text can take, a skill and a plugin, and follows one recorded run with the document plugin. It then shows what the installer checks and which packages it refuses. You need to know what a tool call is; Following a task through the agent loop explains it.

1. What a skill is

A skill is a directory with a file named SKILL.md. The file starts with a short header, called frontmatter, that holds a name and a description. The rest is the instruction text. This is the beginning of the debugging skill that ships with agentkit; the shipped skills are written in German, as are agentkit's own prompts:

---
name: fehlersuche
description: Einen Fehler systematisch eingrenzen und beheben — reproduzieren,
  Ursache finden, gezielt korrigieren, mit Test absichern. …
---

# Fehler suchen

Rate nicht. Jeder Schritt erzeugt einen Beleg, der die nächste Vermutung trägt oder
widerlegt.

## Schritt 1 — reproduzieren
…

The agent does not receive the whole file with every request. It receives a tool named list_skills, which returns the names and descriptions, and a tool named read_skill, which returns the body of one skill. The model reads a body when a description matches the task. A skill you never use therefore adds only its description to that list.

Until now a skill directory had to be named with --skills DIR on every call. That works for a repository that carries its own skills. It is inconvenient for a procedure you want in every project.

2. Installing a skill

The new skills verb copies a skill into agentkit's configuration directory, ~/.agentkit on Linux and %USERPROFILE%\.agentkit on Windows:

agentkit skills install fehlersuche     # by name, from the release package
agentkit skills install --all           # every skill in the release package
agentkit skills install ./my-skill      # a local directory or a package file
agentkit skills list
agentkit skills remove fehlersuche

Installing by name downloads the file agentkit-skills.json from the latest stable release of the agentkit repository. The packages are attached to releases from 0.33.0 on; with that release, agentkit skills install diff-review and agentkit plugins install dokumente installed by name in a test. A candidate release such as 0.33.0-rc.6 does not count as the latest stable release. To install a candidate's packages, download the package file from the candidate's release page and install it by path. The first package contains four coding skills: writing a commit message, reviewing a diff, tracking down a bug and writing tests.

Every later run loads the installed skills without a flag. This applies to a single task, the interactive session (--repl), the terminal interface (--tui) and the two integrations for editors and other agents, acp and mcp-serve. Two rules decide what happens when several sources are present:

  • Order. Skills from --skills come first, then installed skills, then the skills of plugins. If two have the same name, the first one found is used.
  • Tool selection. A run with --tools loads nothing that was installed. Such a run is usually a step in a pipeline, and a note about skills in its prompt would change its behavior.

In a test with 0.33.0-rc.6, a run asked for its available skills listed all installed ones, and the same question with --tools none reported none.

3. What a plugin adds

A skill is one procedure. The contract example needs more: a procedure for evaluating one document, another for comparing two, and a way to start the agent with a prompt written for documents instead of code. A plugin bundles these parts under one name and one version:

dokumente/
  plugin.json                           name, version, description
  commands/dokumente.md                 a system prompt with settings
  skills/dokument-auswerten/SKILL.md    evaluate one document
  skills/dokumente-vergleichen/SKILL.md compare two documents

A plugin can contain three kinds of parts. Skills have the format described above. A command is a Markdown file whose frontmatter holds settings, such as the maximum number of steps a run may take, and whose body becomes the system prompt; you start it with agentkit run NAME. A role, stored under agents/, describes a helper agent for the task tool, as covered in Delegating work to sub-agents. Every part is a text file.

The plugins verb has the same subcommands as skills, plus enable and disable. A disabled plugin stays installed, and its parts are not loaded.

4. A recorded run with the document plugin

The following run used agentkit 0.33.0-rc.6 on Windows with the model gpt-6.1-terra on Azure OpenAI. The document was a 500 KB PDF of a German public-sector collective agreement (TV-L). The four coding skills had been installed beforehand with agentkit skills install ./agentkit-skills.json. The plugin was installed from agentkit-plugins.json; both files are attached to the 0.33.0-rc.6 release on GitHub. tvl.pdf is the author's test file in the working directory, and reading a PDF requires a build with PDF support, which the release binaries have. The commands were run in Git Bash. The original question was German; it is translated here:

agentkit plugins install ./agentkit-plugins.json
agentkit run dokumente -y "How long is the probation period according to tvl.pdf,
  and are there exceptions? Answer briefly and cite the passage."

-y skips the approval prompt for shell commands. The trace on standard error showed these steps of the main agent:

StepTool callResult
1list_skillsSix skills: four installed coding skills and the plugin's two
2glob_filesFinds tvl.pdf
3doc_ingestSplits the PDF into 91 section files under .agentkit/docs/tvl/
4read_file on index.mdThe outline with section titles and page ranges
5grep for the German word for probationMatches in three section files
6read_file on three sectionsThe paragraphs with their page ranges

Steps 3 to 6 are the procedure from the plugin's prompt. doc_ingest is a tool that splits a PDF, Markdown or text file at its headings into section files containing the original wording, each with its page or line range in the header. The main agent then worked on the sections that the search pointed to and did not read the document as a whole.

The answer named six months as the general rule, a shorter period if agreed, and no probation period when an apprentice is taken on directly after the apprenticeship, citing § 2 (4). For fixed-term contracts it named six weeks without an objective reason and six months with one, citing § 30 (4). Both paragraphs contain these statements in the section files; the page numbers given in the answer were not checked separately.

The run took 91 seconds and reported 95,923 input tokens, of which 68,699 came from the provider's cache, and 1,345 output tokens. Part of that came from two helper agents the main agent started after step 6: an explorer, which failed with a network error, and a reviewer, which called read_pdf on the whole file before confirming the answer. The plugin's prompt does not mention helpers. The task tool belongs to the standard tool set, and the model chose to use it. A command can set no_subagents to remove that tool; the document plugin does not.

A second doc_ingest call on the same file reported that the document was already split and wrote nothing. After a paragraph was appended to a Markdown source, the tool rewrote that bundle and told the model that earlier section numbers no longer apply.

5. What the installer refuses

Installed text reaches the model in later runs, and a command can change settings. agentkit also has two mechanisms that start programs without asking: hooks, which are shell commands run before or after a tool call, and MCP servers, which are external programs that offer additional tools. A package from someone else should not be able to bring either. agentkit enforces this in the package format and in a check of every entry.

A package is a JSON file that maps relative paths to file contents. The format has no way to express a symbolic link, a binary file or a file mode, and installed files receive the default permissions. File names are not restricted to Markdown, so a package may contain a file such as helper.cmd. agentkit does not start such a file on its own. Before anything is written, the installer checks each entry. Only then does it write the files to a staging directory and rename that directory into place. A failed check leaves no partial installation.

The following packages were built by hand and offered to 0.33.0-rc.6. Each was refused with exit code 1, and none left a file behind. The installer's messages are German and are summarized here:

The package containedReason given
A path ../../evil.md or C:/evil.mdPath not allowed
A file named .envPath not allowed; hidden files are excluded
A file named CONReserved name on Windows
A plugin with hooks/hooks.jsonHooks run code without approval
A plugin.json declaring mcpServersPlugins may not bring executable code
A command with yes: true or workspace: C:/Setting not allowed in a plugin command

The last row deserves an explanation. A command's frontmatter can set options that a command line can also set. For a command you wrote yourself, that is the point. In a plugin, some options would remove a protection: yes skips shell approval, workspace and allow_read widen the directories the file tools may touch, and hooks or mcp_config name hooks and MCP servers to start. A plugin command may therefore set only a fixed list of options, among them strategy, max_steps, model and timeout. You can still pass -y yourself, as in the run above.

The check runs again each time a command is loaded. When the installed command file was edited afterwards to add yes: true, agentkit run dokumente stopped with exit code 3 and named the setting. The rules are implemented in packages.rs.

These checks cover the package: its paths, its parts and its settings. The instructions themselves are not reviewed. A skill can still instruct the model to do something you would not want, and the model may follow it within the permissions of the run. Read a skill from another author before installing it, as you would read a script.

6. Packaging your own

A skill of your own needs a directory with a SKILL.md. The name may contain lowercase letters, digits and hyphens. Install it from the directory, or build a package file to pass on:

# Bash
agentkit skills install ./release-notes
agentkit skills pack ./release-notes > my-skills.json
agentkit plugins pack ./my-plugin > my-plugins.json

pack applies the same checks as install, so a package that can be built can also be installed. Replace the directory names with your own. A plugin directory needs a plugin.json whose name matches the plugin; version and description are optional and appear in agentkit plugins list. A package file must be UTF-8 text. Windows PowerShell 5.1 writes UTF-16 when output is redirected with >, so use PowerShell 7 or Bash for the two pack commands.

agentkit downloads packages only from its own releases. To share a package, pass the file on and install it by path. There is no registry and no dependency handling between plugins.

7. Costs and limits

Every installed skill adds its description to the list the model can request. A handful of skills is cheap; a large collection makes the list longer for the model to read. Remove skills you do not use, or disable a plugin while you do not need it.

In the recorded run, the document command also listed the four coding skills, which have no use for a question about a contract. The release 0.33.0 changes this: a command that belongs to a plugin loads only the skills of its own plugin, and --skills on the command line still adds to them. A run without a plugin command loads all installed skills as before. With 0.33.0, a run of agentkit run dokumente asked for its available skills listed only the plugin's two.

A skill is an instruction to a model. The model decides whether to read it and how closely to follow it. The recorded run followed the document procedure and still started helpers that the procedure does not call for.

The formats overlap with Claude Code in part. Skills and roles use the same file format. Commands differ: in Claude Code a command's text is a user prompt, while in agentkit it is a system prompt. A Claude Code plugin can therefore not be installed directly, and a plugin containing a .claude-plugin/ directory is refused.

8. Summary

A skill is a procedure in a SKILL.md file that the model reads when its description fits the task. agentkit skills install stores it so that later runs load it without a flag. A plugin bundles skills, roles and commands under one name; a command starts the agent with its own system prompt through agentkit run NAME. Packages contain text only, every entry is checked before it is stored, and a plugin command cannot switch off approval or widen file access.

The capability guide lists the commands. The source of the document plugin is in examples/dokumente/plugin, and the four coding skills are in agentkit_app/skills.

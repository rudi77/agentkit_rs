Rust · synchronous · offline by default · MIT

An agent is an LLM in a loop with tools.

agentkit takes that one sentence seriously. It is a small agent framework and a complete coding agent, written in Rust with no async runtime, and every larger capability — context management, swarms, a knowledge graph, a persistent work runtime — is built around the loop, never into it.

What it is

A framework you can read top to bottom

The core of agentkit is one function, Agent::drive, and a handful of modules that map one-to-one onto a Python original. Everything a frontend or an extension needs comes out of the loop as a typed event stream. That is what makes the rest of the system possible without touching the core: the terminal UI, the Unix-filter CLI, sub-agents, swarms and the trace viewer are all just consumers of the same events.

library

agentkit

The agentic loop with its harness: streaming, retries with backoff, parallel tool calls, cancellation, memory compaction. Tools, skills, planning, sub-agent roles, MCP, and the logic behind the CLI, REPL and TUI.

library

ctxman

Context management as memory management: a watermark-driven garbage collector, a content-addressed blob store, LLM-backed compaction with fact promotion, and a byte-stable render pipeline for stable prompt caches.

library

agentkit-swarm

Actor-based agent-to-agent collaboration: one thread and one bounded mailbox per agent, peer-to-peer tools, consensus-based completion — and a swarm tool that lets an agent assemble its own swarm at runtime.

library

agentkit-graph

Knowledge that outlives a session: a working graph for the current task, a canonical graph for durable facts, provenance on every claim, stored as a plain-Markdown OKF bundle. No database, no C compiler.

library

agentkit-work

A runtime for work that outlives a single run: work items with dependencies, leases, attempts, artifacts, retries, budgets and verification, journaled to append-only JSONL so a crash costs at most the running attempt.

tool

agentkit-viz

An observation tool that reads the NDJSON trace of a run and shows agents, histories, context, timeline, swarm traffic, graph and work in the browser — live or after the fact, read-only, localhost only.

executable

agentkit-app

The installable agentkit binary: a thin wiring crate that knows all the libraries and is the only place where they meet. Ships as static binaries for Linux and Windows.

harness

agent_benchmarks

A Python harness that runs the agent headless against SWE-bench Lite, Terminal-Bench 2.0 and Aider Polyglot, inside each benchmark's own task containers.

Why it feels different

Boring on purpose

No async runtime

There is no tokio anywhere in the repository. HTTP is synchronous, MCP is a mutex-guarded stdio session, parallel tool calls are scoped threads, and each swarm member is one OS thread owning one agent. The result is code you can step through, and a static musl binary that runs in any container.

Offline by default

Every crate builds and tests with zero HTTP or TLS dependencies. No test touches the network: the loop is exercised with a scripted fake model, and the context manager is pinned by byte-exact golden fixtures from its reference implementation.

One-way dependencies

The agent core does not know the swarm, the graph or the work runtime. They depend on it, never the other way round. The single extension seam — a closure that registers extra tools before the agent is built — exists for exactly one reason and is documented as such.

Identity comes from the runtime

No tool that writes to shared state has an argument for who is writing. A swarm member cannot impersonate a peer, a graph writer cannot choose its scope, a work attempt cannot claim another item. These are structural facts, not validations.

Three shapes of work

Pick the smallest form that fits

SituationReach forWhy
A clear task, one agent, a few minutesagentkitOne loop with sandboxed tools, sub-agents on demand. Cheapest and most predictable.
Several perspectives, a short collaborationthe swarm toolPeers that negotiate over multiple rounds, each with its own memory, closing on a quorum rather than one agent's judgement.
Many steps, long runtime, resume after a crashagentkit workPersistent work items, leases and attempts; agents stay short-lived while the work state lives for hours.

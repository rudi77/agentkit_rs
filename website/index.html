Run a language model with tools.

agentkit is a coding assistant and a Rust library for building agents. Give it a task, and the model can request files, make edits and run commands. agentkit executes those requests and returns the results to the model so it can decide what to do next.

This is one possible run. For an editing task, the model may repeat the cycle to change code, inspect test output and revise its work.

Start with one task

After installing agentkit, you can check that it runs without connecting a model:

agentkit --demo "What is 17 + 25?"

The built-in demo returns 42 through a scripted tool interaction. To work on your own files, configure a model, open a terminal in your project directory and give it a specific question:

agentkit "Read README.md and explain how to run this project."

The current directory is the default workspace for file tools. You can follow the tool calls in the terminal, continue the conversation with --repl, or use the terminal interface with --tui.

If you are embedding an agent in a Rust application, start with the library example. You supply the model and tools; the library runs the interaction between them.

When a task needs more than one conversation

A longer task raises several different problems. The conversation may grow too large for the model, several agents may need to exchange findings, or work may need to survive a restart. agentkit has a separate component for each of these needs.

Keep useful context

ctxman manages the material sent to the model. It can save large tool results outside the prompt, retain references to them and summarize older conversation content.

Delegate a bounded question

A sub-agent can investigate a file or review a change with its own conversation. Its result returns to the agent that requested it.

Let agents discuss a result

A swarm gives agents mailboxes and tools for exchanging messages. They can propose a result and vote on it over several rounds.

Reuse findings later

The knowledge graph records claims together with their sources. Later tasks can retrieve relevant findings without loading an entire previous conversation.

Resume a longer project

The work runtime stores tasks, dependencies, attempts and output files. After an interruption, it uses those records to determine what remains to be done.

Inspect what happened

The trace viewer shows model output, tool calls and agent activity in a browser. Use it during a supported run or open the trace afterwards.

Choose how to run the work

For a file explanation or a small change, begin with an ordinary agent task. Add collaboration when you can describe what each participant should contribute. Use persistent work items when tracking progress across attempts matters.

Read the implementation

The core uses synchronous model calls and ordinary Rust threads for concurrent tools. Tools are registered explicitly, and each run publishes events that the terminal and trace writer can consume. The architecture guide follows a request through these parts and links to their source.

The library includes a scripted model for offline tests. This lets you check tool execution and event handling without an API key. Network support and larger components are selected through Cargo features; release binaries include the features described in the installation guide.
